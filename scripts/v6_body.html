내용

추후 취할 조치

1

Gemini를 메인 API가 직접 호출하고 있고, 키가 작성자 개인 것이다
팀 표준은 GPU image-processor가 SAM 3 분할 → Gemini 캡셔닝 → FashionSigLIP 임베딩까지 하고 콜백으로 돌려주는 경로다. 이 브랜치는 데모를 굴리려고 메인 API에서 동기 호출로 붙였고, 그래서 세그멘테이션·임베딩·Qdrant upsert가 통째로 빠져 있다.

PR 전 되돌린다.
① 개인 키 → 팀 공용 키(Infisical)
② image-processor 콜백 경로로 이관.
②를 하면 빠진 임베딩도 같이 채워진다

2

공유한 옷이 코디 추천 검색에 안 잡힌다
Qdrant 옷장 검색은 user_id를 필수 필터로 강제하고(retriever.py:769-771), payload에 방 정보가 없다(vectors.py:67). 그래서 남이 올린 공유 옷은 검색 결과에 원천적으로 안 나온다. 방 화면에는 잘 보이는데(그건 DB 조인이라) 추천 엔진만 못 보는, 눈에 안 띄는 불일치다.

해결안 A(payload에 방 정보 추가) / B(공유 옷은 DB로 id 뽑아 2단계 검색) 중 택1.

제안은 B — 격리 규칙을 payload 동기화라는 깨지기 쉬운 상태에 맡기지 않는 쪽. 옷장·추천 담당과 합의 필요

3

confirmed=True 가드가 docstring에만 있고 코드에 없다
분석 확정 전(confirmed=False) 옷도 공유방에 올라간다. 이 옷들은 추천 검색 대상에서 제외되므로, 방에는 보이는데 추천에는 안 쓰이는 옷이 생긴다.

docstring을 코드에 맞춰 내리거나, 필터를 넣거나 둘 중 하나로 정리

2번은 1번에 의존한다. 1번을 되돌려 image-processor 경로로 가야 공유 옷의 벡터가 애초에 Qdrant에 들어간다. 지금 데모 경로는 임베딩 자체를 만들지 않으므로, A든 B든 그 전에는 검증할 수 없다.
