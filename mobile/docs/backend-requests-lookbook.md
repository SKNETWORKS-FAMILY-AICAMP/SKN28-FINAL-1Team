# 룩북 개편에 필요한 백엔드 요청

프론트에서 룩북 구조를 바꾸면서(2026-08-13, `feature/front-lookbook-redesign`) 서버 쪽이 있어야
끝나는 항목만 모았다. 프론트는 이 두 가지 없이도 동작하지만, 없으면 사용자가 보는 결과가 반쪽이다.

## 1. 사진에서 뽑은 옷을 옷장에 바로 넣지 않기

**지금**: 사진으로 룩을 올리면 서버가 옷을 추출해 `wardrobe_item_id` 를 만들어 붙인다
(`LookbookWardrobeItem.link_type`). 그 순간 옷장 아이템이 되어 **사용자가 고르지 않은 옷이
옷장에 쌓인다.**

**원하는 동작**: 추출은 그대로 하되 옷장에는 넣지 않는다. 사용자가 룩 상세에서 아이템마다
'옷장에 추가'를 눌렀을 때 비로소 옷장에 들어간다.

**필요한 것 (둘 중 하나)**
- `LookbookWardrobeItem` 에 `in_wardrobe: boolean` 같은 필드 + 옷장 편입 엔드포인트
  (`POST /api/v1/lookbooks/{id}/items/{link_id}/add-to-wardrobe/` 형태)
- 또는 추출 결과를 옷장과 분리된 테이블에 두고, 편입 시점에 옷장 아이템을 생성

**프론트 상태**: 룩 상세의 아이템별 '옷장에 추가' 버튼은 이미 있다. 위 필드가 오면
"이미 옷장에 있음" 과 "아직 아님" 을 갈라 버튼을 그리면 된다.

## 2. 룩 전체공개 여부

**지금**: `LookbookPost` 에 공개 범위 필드가 없다. 모든 룩이 사실상 비공개(내 목록에서만 보임)다.

**원하는 동작**: 사용자가 룩을 올릴 때 '전체 공개'를 켜면 **앱 사용자 전체가 둘러보기에서 본다.**
친구 단위 공유는 룩북에서 없앴다(옷 공유는 옷장의 '공유 옷장'이 맡는다).

**필요한 것**
- `LookbookPost.is_public: boolean` (기본 false) — 등록·수정 시 지정
- 공개 피드 조회 `GET /api/v1/lookbooks/public/` — 앱 기본 제공 룩 + 전체공개된 남의 룩

**프론트 상태**: '둘러보기' 피드는 아직 **로컬 시드**(`state/lookbook.ts`)다. 위 API 가 오면
그 자리를 그대로 대체한다. 그전까지 전체공개 토글은 만들지 않았다 — 켜도 아무 일도 일어나지
않는 스위치를 두면 켠 줄 알고 넘어가기 때문이다.
