# 골든셋 선정 기준 — 무엇을 넣고 무엇을 빼는가

- **작성일**: 2026-08-06
- **선행**: [README.md](../README.md)
- **목적**: "왜 이게 골든셋인가"에 답하고, **나중에 항목을 추가할 때 쓸 통과 조건**을 정의한다

---

## 1. 왜 기준이 먼저 필요한가

골든셋은 "좋아 보이는 규칙 모음"이 아니다. 추천 결과를 **거절할 권한**을 가진 규칙이다.
근거 없는 규칙이 하나 섞이면, 그 규칙에 걸린 좋은 추천이 조용히 사라지고 원인을 추적할 수 없다.

그래서 항목을 넣기 전에 **5개 축을 전부 통과**해야 한다. 하나라도 실패하면 골든셋이 아니라
knowledge 청크(설명용)로 강등한다.

---

## 2. 통과 조건 5축

| 축 | 질문 | 실패 시 처리 |
|---|---|---|
| **C1. 검증 가능성** | 근거가 실측 데이터·공개 표준·팀 문서 중 하나에 있는가? "일반적으로 그렇다"는 근거가 아니다 | knowledge 청크로 강등 |
| **C2. 결정 가능성** | 우리 taxonomy 필드만으로 자동 판정되는가? 사람의 눈이 필요하면 규칙이 아니다 | 필드를 먼저 추가하거나 보류 |
| **C3. 재현성** | 원천이 갱신되면 스크립트 재실행만으로 값이 갱신되는가? | `tools/`에 생성 스크립트 추가 |
| **C4. 안정성** | 시즌·유행이 바뀌어도 유지되는가? "올해는 버건디" 같은 건 골든셋이 아니다 | 트렌드 데이터로 분리 |
| **C5. 반증 가능성** | 이 규칙이 틀렸다면 어떤 지표에서 드러나는가? | 지표를 정의할 수 없으면 채택 보류 |

### 축을 이렇게 잡은 이유

- **C1·C4**는 규칙의 **수명**을 지킨다. 감으로 쓴 규칙과 유행 규칙은 6개월 뒤 아무도 손대지 못한다.
- **C2**는 규칙을 **실행 가능**하게 한다. 판정에 필요한 태그가 없으면 그 규칙은 문서 속 장식이다.
  실제로 세로축(상하체 비율) 규칙이 여기서 걸렸다 — [02번 문서 §4](02-body-proportion-rules.md) 참조.
- **C3**은 **모순**을 막는다. 136쌍을 손으로 적으면 반드시 앞뒤가 다른 칸이 생긴다.
- **C5**는 골든셋과 취향을 가른다. 반증할 수 없는 규칙은 검증할 수도 없다.

## 3. 제외 조건 (하나라도 해당하면 넣지 않는다)

1. **개인 취향에 속하는 것** — 이미 `style_preferences`(선호/기피 색·핏)가 담당한다. 골든셋이 취향을 덮어쓰면 안 된다.
2. **날씨·TPO 판단** — `filter_rules.py`(문서 4 P0)의 영역이다. 두 곳이 같은 판단을 하면 충돌한다.
3. **사이즈 적합성** — 옷장 아이템은 이미 소유한 옷이라 판정 대상이 아니다 (문서 4 §1-2).
4. **특정 브랜드·상품에 종속된 규칙** — 상품 DB가 바뀌면 무효가 된다.
5. **하드 필터로 쓸 수 없는 애매한 규칙** — "약간 어울린다" 수준은 `should` 가중치이지 규칙이 아니다.

## 4. 현재 수록 항목의 기준 통과 내역

| 항목 | C1 검증 | C2 결정 | C3 재현 | C4 안정 | C5 반증 | 판정 |
|---|---|---|---|---|---|---|
| v2 색 17종 속성 (CIELCh) | ✅ 레퍼런스 팔레트 + 대표 hex | ⚠️ 매핑표 경유 필요 | ✅ 스크립트 | ✅ | ✅ 조합 등급 오탐률 | **채택** |
| 색 조합 등급 136쌍 | ✅ 규칙 R1~R6에서 유도 | ⚠️ 매핑표 경유 | ✅ 스크립트 | ✅ | ✅ 기피 조합 노출률 = 0 | **채택** |
| 태그↔팔레트 매핑표 | ⚠️ 수기 판단 | ✅ `color` 태그 | ➖ 수기 (검증 스크립트 있음) | ✅ | ✅ 매핑 오분류율 | **조건부 채택** — 손실 6건 명시, `블루`·`멀티`는 잠정 |
| 레퍼런스 등급표 (추출본) | ❌ 셀 검출 실패 | ❌ | ❌ | — | — | **기각** — `grade_map_extracted.json`은 참고 기록으로만 보존 |
| 체형 5분류 임계값 | ✅ 사이즈코리아 181명 | ✅ shoulder/waist/hip | ✅ 스크립트 | ✅ | ✅ 분류 분포 편중도 | **채택** |
| 체형별 핏·기장 권장 | ⚠️ 수기 (실측 근거 아님) | ✅ `fit`·`length` 태그 | ➖ 수기 JSON | ✅ | ✅ human eval 선호도 | **조건부 채택** — `should` 가중치로만 사용, 하드 필터 금지 |
| 상하체 비율 규칙 (`torso_ratio`) | ⚠️ 수기 | ❌ **입력 없음** | ➖ | ✅ | ✅ | **보류** — C2 실패. 입력 확보 후 재심사 |
| 목 길이 규칙 (`neck_length`) | ⚠️ 수기 | ❌ **입력·태그 둘 다 없음** | ➖ | ✅ | ✅ | **보류** — C2 이중 실패. 사용자 입력과 `neckline` 태그가 둘 다 필요 |
| 허벅지:종아리 규칙 (`thigh_calf_ratio`) | ⚠️ 수기 | ❌ **입력 없음 (컬럼은 있으나 둘레)** | ➖ | ✅ | ✅ | **보류** — C2 실패. `do_not_use`로 오용 차단 명시 |

> **조건부 채택의 의미**: C1이 수기라 "이 체형엔 이 핏이 옳다"를 단정할 근거가 없다.
> 그래서 후보를 **잘라내지 않고(`must_not` 금지) 순위만 올린다(`should`)**.
> K-Fashion 공출현 통계로 근거가 채워지면 승격을 재심사한다.

---

## 5. 항목 추가 절차

1. `*/rules/`의 JSON에 항목을 추가한다 (MD가 아니라 JSON이 먼저다).
2. 위 5축 표에 한 줄을 추가하고 각 축의 근거를 적는다.
3. C1이 데이터 근거라면 `tools/`에 산출 스크립트를 추가한다 (C3 충족).
4. C1이 수기라면 **`should` 전용**으로 표시한다 — 수기 규칙은 후보를 잘라낼 수 없다.
5. 설명이 필요하면 해당 MD 문서에 서술을 추가한다. **숫자는 JSON에서 인용만 한다.**

## 6. 갱신 규칙

| 트리거 | 해야 할 일 |
|---|---|
| taxonomy COLORS/FITS/LENGTHS 변경 | `validate_color_map.py` 실행 → 매핑표 갱신 → 생성 스크립트 재실행 |
| v2 팔레트 변경 (예: `Blue` 추가) | `build_color_rules.py` 재실행 + `validate_color_map.py`로 미사용 색 확인 |
| 사이즈코리아 표본 추가 | `derive_body_thresholds.py` 재실행 → 분류 분포에 빈 클래스 없는지 확인 |
| Confluence 규칙 문서 갱신 | 충돌 시 **Confluence가 우선** (팀 합의 원본) |
| 평가에서 기피 조합 노출률 > 0 | 규칙 누락이 아니라 **필터 미적용**을 먼저 의심 |
| human eval에서 특정 규칙의 선호도가 무작위 수준 | 해당 규칙을 `should`에서도 제거 검토 |

## 7. 미해결 / 확인 필요

1. **Confluence 체형·색상 규칙 페이지 내용** — 미확보. 이 문서의 규칙과 병합 필요.
2. **Google Drive 골든셋 폴더 내용** — 미확보. 위 5축으로 심사한 뒤 병합.
3. **체형 분류 체계 확정** — 문서 4 §7의 미확정 #3(3분류 vs 5분류)을 **가로축 5분류로 해소**했다. 팀 승인 필요.
4. **세로축 3종 입력 방식** — [02번 문서 §4-4](02-body-proportion-rules.md)의 3개 안 중 택1 필요.
   3축 모두 같은 결정에 묶여 있다(pose 추출 1회로 세 값이 한 번에 나온다).
5. **퍼스널컬러 4계절 체계의 위치** — `tools/gen_personal_color.py`가 4계절 팔레트를 쓰는데,
   이는 골든셋이 현재 모델링하지 않는 **새 축**(피부·모발·홍채 진단 입력이 필요)이다.
   새 축으로 채택할지 범위 밖으로 둘지 결정 필요. 현재는 예시 이미지 생성 용도로만 쓰인다.
