# 외부 신체치수 데이터 소스 트리아지 (2026-08-03)

VLM 신체 계측 벤치마크용 **"전신 이미지 ↔ 실측 치수" 쌍**을 외부에서 확보하려고
여러 소스를 시도했다. 이 문서는 각 소스의 **구조적 성패 원인**을 기록한다.

## 0. 판정 기준 — 행(row) 수가 아니라 "distinct 치수 튜플" 수

쇼핑몰류 소스는 **소수의 전속 피팅 모델**을 카탈로그 전체에 재사용한다.
따라서 상품 페이지를 아무리 많이 긁어도 `(height, bust, waist, hip)`의
**서로 다른 값의 개수**가 늘지 않는다.

> 벤치마크 관점에서 N장의 이미지가 1개의 정답 치수를 공유하면, 유효 표본은 1이다.
> 오히려 행 수만 부풀어 "데이터가 많다"는 착시를 만들기 때문에 **음(-)의 가치**를 가진다.

**새 소스를 붙이기 전 반드시 통과해야 할 스모크 테스트**
1. 상품 페이지 ~30개 샘플링
2. `len(set(tuples)) / len(tuples)` 계산
3. 비율이 0에 가까우면 **즉시 폐기**. 크롤러를 더 쓰지 않는다.

### 1-1. OrangeBear — 폐기 사유 (두 축 모두 실패)

**치수 축**: 수집된 5건이 모두 `H166 / W52 / B86.36 / W68.58 / H86.36`.
`download_orangebear.py`가 파싱하는 `試穿報告`(착용 리포트) 테이블은
**브랜드 전속 피팅 모델 1명의 스펙**이다. 상품이 바뀌어도 모델은 그대로다.
→ ID 범위를 넓혀도 distinct는 1로 고정. 구조적 한계이지 샘플링 문제가 아니다.

**이미지 축**: `og:image`는 전신 사진이 아니라 **상품 썸네일/배너**다.
실제 확인 결과 `OB_11964709_0.jpg`는 남녀 모델 2인 + 로고 + 텍스트가 합성된
마케팅 이미지이며 발목 아래가 잘려 있다. 계측 입력으로 쓸 수 없다.

### 1-2. ModCloth — 폐기 사유 (이전 세션 판정이 **오탐**이었음)

이전 세션은 상품 30개 중 20개에서 "치수 키워드 발견!"으로 판정했으나,
**정규식이 JavaScript 번들 안의 `modelContext` 식별자에 매칭된 결과**였다.

검증 방법: HTML에서 `<script>/<style>/<noscript>` 블록을 **먼저 제거한 뒤**
동일 정규식을 적용.

```
스크립트 제거 전 : "Model..." 매칭 20/20  → 전부 modelContext (JS)
스크립트 제거 후 : 유효 튜플 0/12
```

→ ModCloth 상품 설명에는 모델 치수 정보가 **존재하지 않는다**.
추가로 잦은 `IncompleteRead`(봇 차단성 응답 절단)로 안정 수집도 불가능.

**교훈**: 텍스트 키워드 스캔은 `<script>` 제거를 선행하지 않으면 신뢰할 수 없다.
프론트엔드 번들에 `model`, `size`, `measurement` 같은 흔한 식별자가 대량으로 들어있다.

동시성을 올린다.

## 2. 신규 검증 소스 (2026-08-03 실측)

### 2-1. `Yuanhao-Harry-Wang/fitvto-100k` (HuggingFace)

스키마는 계획서 가정과 **일치**한다. 이전 401은 잘못된 접근 경로 탓이며,
`gated: false / private: false`로 공개 데이터셋이다.

```
features : cloth(Image), target(Image), person(Image),
           body_bust, body_height, body_hips, body_waist (float32)
splits   : train 100,000 / eval 5,000
저장형태 : parquet 426 shard, 총 211.5 GB
해상도   : 768 × 1024
```

**실측 표본 결과** (eval shard 0, row group 0, 50행 + rows API 240행)

| 항목 | 값 | 판정 |
|---|---|---|
| distinct 치수 튜플 | 50행 중 35 (70%) | ✅ 1레코드=1사람에 근접 |
| 키 범위 | 149.8 ~ 195.7 cm | ✅ 골든셋보다 넓음 |
| 가슴 / 허리 / 엉덩이 | 83.9~144.9 / 63.0~141.2 / 87.6~149.4 | ✅ 비만 체형까지 포함 |
| **전신 프레이밍** | **50장 중 14장만 전신 (28%)** | ❌ **계획서 전제 오류** |

> 계획서 `fitvto_download_plan.md`는 "머리끝부터 발목까지 노출이 보장된"을
> 전제로 무필터 순차 수집을 설계했다. **실제로는 72%가 허벅지에서 잘린다.**
> 필터 없이 50명을 뽑으면 그중 36명이 계측 불가 이미지가 된다.

판정 기준(검증됨): 배경색 대비 **최하단 8행의 비배경 픽셀 비율 > 5%** 이면 잘림.
육안 대조로 정확도 확인 완료.

**남는 제약**
- **이미지 종류가 섞여 있다.** 회색 스튜디오 배경의 CGI 렌더(A자세)와
  실사 이커머스 촬영본이 함께 들어 있다. 육안 확인 결과 둘 다 상당수 존재한다.
  - 실사가 섞여 있는 점은 "실사용 도메인 갭" 관점에선 오히려 **유리**하다.
  - 대신 **포즈가 표준화돼 있지 않다.** 손을 허리에 얹거나 다리를 비스듬히
    두는 컷이 있다(예: `FV_008`). 골든셋의 규격화된 정면 직립 자세와 달라
    성능을 직접 비교할 때 교란 요인이 된다.
- **정면만** 있다. 골든셋의 front+side 구조와 맞지 않는다.
- 가상피팅 데이터라 **의상이 무작위 조합**된다. 헐렁한 상의·롱스커트가
  허리·다리 실루엣을 가려 계측 난이도를 왜곡한다.
  실제로 `FV_017`(허리 실측 122.2 cm)은 오버사이즈 상의가 허리를 완전히 덮는다.
  → **치수를 가리는 의상**은 이 데이터셋의 가장 큰 잡음원이다.
    파일럿을 육안 검수해 사용 가능 여부를 먼저 판정해야 한다.
- 🔴 **라이선스 `CC-BY-NC-ND-4.0`** — 비상업적 + 2차저작물 금지.
  본 프로젝트는 상용 서비스를 전제하므로 **학습 데이터로는 사용 불가**,
  내부 평가용도 ND 조항상 파생 데이터셋 생성이 걸린다. 법적 검토 필요.

### 2-2. BodyM (AWS Open Data, `s3://amazon-bodym`)

**무인증 접근 가능**(`--no-sign-request`). 즉시 사용 가능한 유일한 대규모 소스.

🔴 **결정적 제약: 이미지가 RGB 사진이 아니라 이진 실루엣 마스크다** (720×960, 흑백 2색).
프라이버시 때문에 원본 사진 대신 마스크만 공개한 것으로 보인다.

→ 반면 **실루엣 기반 회귀 / 타원 픽셀 분석 / 치수 회귀 모델(TabPFN 등) 검증에는 최적**이다.
   정면+측면이 모두 있어 raw_test_data와 구조가 같다.

## 4. 권고 수집 방안

### fitvto-100k — 무필터 수집 금지, **필터 우선** 스트리밍

계획서의 `step_skip = 10` 균등 스킵 방식은 두 가지 이유로 폐기한다.

1. 프레이밍 필터가 없어 표본의 72%가 계측 불가 이미지가 된다.
2. `load_dataset(streaming=True)` + `next()` 스킵은 shard를 순차로 훑으므로
   211 GB 중 앞쪽 shard에만 편중된다. 체형 다양성 확보라는 목적에 반한다.

대신:
- **shard를 흩어서** 읽는다 (426개 중 무작위 shard의 row group만 선택).
- 각 행마다 **하단 8행 배경 대비 점유율 검사**를 통과한 것만 채택.
- 채택된 것 중 **치수 튜플 중복 제거**.
- 목표 수량을 채울 때까지 반복.

### BodyM — 용도를 분리해서 사용

VLM 벤치마크셋에 섞지 않는다. 실루엣 회귀·치수 회귀 전용 세트로 분리한다.

## 4-1. 파일럿 실행 결과 (2026-08-03, 20명)

스크립트: `ml/scratch/download_fitvto_eval.py` (`--target 20 --seed 42`)
산출물: `ml/body_measurement/data/fitvto_eval/` (**gitignore 처리됨** — NC 라이선스)

```
확보 20명 / 스캔 87행
  하단 잘림 제외 49  (56%)
  치수 중복 제외 18  (21%)
  전신 통과율 23.0%
분포: 키 158.5~195.7 / 가슴 87.9~129.6 / 허리 68.3~122.2
출처 shard: eval 0004, 0005, 0009, 0014, 0019 (6개에 분산)
```

### 도중에 잡은 함정 — shard 군집

첫 실행은 shard를 순서대로 끝까지 빨아들여 **20명 전원이 shard 0019에서** 나왔고,
키 범위가 167.0~195.7로 좁아졌다. `--max-per-shard` 상한(기본 `target//5`)을 두고
shard를 여러 바퀴 순회하도록 고쳐 158.5~195.7로 넓어졌다.

> **소표본 수집에서 shard 단위 편중은 눈에 잘 안 띈다.** 총 개수만 보면 정상이고
> 분포를 봐야 드러난다. 수집 스크립트는 항상 분포 요약을 함께 출력해야 한다.

### 🔴 파일럿 판정: **fitvto는 현재 상태로 벤치마크에 부적합**

파일럿 20장 중 7장을 육안 검수한 결과 **6장에서 허리 또는 힙이 의상에 완전히 가려졌다.**

| 샘플 | 실측 | 관찰 | 판정 |
|---|---|---|---|
| FV_000 | W 108.5 | 헐렁한 블라우스가 허리를 덮음 | ❌ |
| FV_001 | Hip 126.6 | 미디스커트가 하체 전체를 가림 | ❌ |
| FV_003 | B 100.2 / W 85.1 | 박시한 오버사이즈 상의, 체형 판독 불가 | ❌ |
| FV_006 | W 72.2 | 박시 상의 + 비대칭 스커트 | ❌ |
| FV_008 | W 68.3 | 몸에 붙는 상의로 체형은 보이나 **비표준 포즈**(손 허리, 다리 각도) | △ |
| FV_017 | W 122.2 | 오버사이즈 상의가 허리 전체를 덮음 | ❌ |
| FV_018 | W 73.7 | 박시 셔츠가 허리를 덮음 | ❌ |

**이건 데이터 결함이 아니라 설계다.** fitvto는 가상피팅(virtual try-on) 데이터셋이라
사람과 의상을 **의도적으로 무작위 조합**한다. 데이터 카드는 `person` 컬럼을
"the same person in a **neutral outfit**"이라 설명하지만, 실제로는 중립적이지 않고
오버사이즈 의상이 다수다. 허리·힙 가림은 예외가 아니라 **기본값**이다.

→ 프레이밍 필터로는 해결되지 않는다. 의상 가림 필터가 추가로 필요하고,
  그건 "몸통에 밀착된 옷인가"를 판정하는 문제라 사실상 또 하나의 비전 모델이 든다.
→ **50명·200명으로 확대하지 말 것.** 확대해도 대부분이 계측 불가 이미지가 된다.

### ⚠️ 추가 의심: 치수 라벨 신뢰도

`FV_001`의 라벨 키는 **195.7 cm**인데 이미지의 인물은 그 정도로 보이지 않는다.
데이터 카드에 **치수 산출 방법이 명시돼 있지 않다**(측정값인지, 추정값인지 불명).
가상피팅 논문의 부산물이라 치수는 부차적 어노테이션일 가능성이 있다.

> 정답 라벨의 출처를 확인할 수 없는 데이터는 벤치마크의 기준으로 쓸 수 없다.
> 이 항목만으로도 fitvto를 기준 벤치마크에서 제외할 사유가 된다.

### 확인된 것 — 전신 필터는 체형을 편향시키지 않는다

필터가 특정 체형만 남기는지 별도 검증했다 (eval shard 3·11, 300행).

| | n | 키 평균 | 키 범위 | 가슴 평균 | 허리 평균 |
|---|---|---|---|---|---|
| 전신 통과 | 93 | 171.8 | 149.8~195.7 | 106.9 | 93.7 |
| 하단 잘림 | 207 | 172.1 | 149.8~195.7 | 104.8 | 90.9 |

두 집단의 분포가 사실상 동일하다. 필터는 **프레이밍만 거르고 체형은 거르지 않는다.**
즉 필터로 인한 표본 편향은 없다고 봐도 된다.

## 5. 검토: SizeKorea CSV → body-visualizer 3D 렌더 (사용자 제안)

`data/sizekorea_measurements_clean.csv`(**5,092명**, gender/height/weight/chest/waist/
hip/thigh/calf/arm/shoulder)를 [body-visualizer.com](https://body-visualizer.com/ko)에
넣어 3D 모델을 만들고, 그 렌더를 벤치마크 이미지로 쓰자는 제안.

### 사이트 실측 확인 결과

| 기능 | 확인 |
|---|---|
| 입력 | 성별·나이·키·체중·근육·비율 + **가슴/허리/엉덩이/팔·다리 둘레/인심** |
| 포즈 | **A 포즈 / T 포즈 프리셋** 제공 |
| 시점 | 모델 회전 자유 → **정면 + 측면 모두 획득 가능** |
| 출력 | 캔버스 정지 이미지 복사·다운로드 |
| 상태 저장 | URL 프래그먼트에 base64 인코딩 (`#m=` + `btoa`) |
| 구현 | Vite SPA + WebGL 캔버스 |

### 이 방식이 해결하는 문제 (fitvto의 실패 원인을 정확히 겨냥한다)

1. **의상 가림 = 0.** 나체 메시라 허리·힙이 항상 보인다. fitvto를 죽인 바로 그 문제.
2. **정답 라벨이 입력값 그 자체.** fitvto의 라벨 신뢰도 의심이 원천적으로 사라진다.
3. **정면 + 측면** 확보 가능 → `raw_test_data`의 front+side 구조와 일치.
4. **포즈 표준화** (A/T 포즈 고정) → fitvto의 비표준 포즈 교란 제거.
5. **한국인 분포.** 5,092명. fitvto의 서구권 이커머스 모델보다 타깃 사용자에 근접.
6. **라이선스 문제 없음.** 자체 보유 데이터의 자체 렌더.

### 🔴 결정적 한계 — 순환 논리 (circularity)

body-visualizer는 **치수로부터 통계적 체형 모델(CAESAR 계열 저차원 PCA 공간)을 풀어
메시를 만든다.** 그 렌더를 VLM에 주고 치수를 맞히게 하면, 측정 능력이 아니라
**"그 파라메트릭 모델을 역산할 수 있는가"**를 재게 된다.

- 렌더 이미지는 입력 치수를 거의 **무손실로 인코딩**한 것이다.
  실제 사진에는 없는 정보가 이미 그림 안에 들어 있다.
- 따라서 여기서 나온 점수는 **낙관적으로 편향**된다. 실사진 성능을 대표하지 못한다.
- 실제 인체는 저차원 PCA 공간이 표현하지 못하는 변이를 갖는다.

### 그 외 한계

- **도메인 갭이 fitvto보다 더 크다.** 나체 회색 메시 · 의상 없음 · 피부 텍스처 없음 ·
  실제 조명/카메라 없음 · 배경 없음. 실사용(사용자 폰 촬영)과 가장 먼 형태다.
- 사이트 스스로 **"대략적인 신체 모델"**이라고 명시한다. 입력 치수가 메시에
  정확히 실현된다는 보장이 없다 → "정답이 정확하다"는 장점이 약해진다.
  **렌더된 메시가 실제로 그 허리둘레를 갖는지 별도 검증이 필요하다.**
- CAESAR 계열 형상 prior는 주로 서구권 스캔에 적합된다. 한국인 치수를 넣으면
  사지·몸통 비율이 실제 한국인과 다르게 나올 수 있다.
- 자동화 비용: 상태가 URL **프래그먼트**에 있어 서버가 볼 수 없다. 즉 피험자마다
  브라우저 렌더링 + 스크린샷이 필요하다. 정면·측면 2장이면 5,092명 × 2 = 1만 장.
  사이트 이용약관상 대량 자동화가 허용되는지 확인 필요.

### 권고 — 벤치마크 대체재가 아니라 **진단 도구**로 쓴다

이 방식의 진짜 가치는 "실사진 벤치마크를 대신하는 것"이 아니라,
**어떤 실제 데이터셋으로도 만들 수 없는 통제 실험**을 가능하게 하는 데 있다.

1. **하한선 진단 (floor test)** — 정보가 온전히 들어 있는 깨끗한 합성 메시에서조차
   치수를 못 맞히면, 실사진에서는 확실히 못 맞힌다. 값싸고 결정적인 디버깅 신호.
2. **민감도 분석 (sensitivity analysis)** — 다른 조건을 고정하고 허리만 60→110으로
   변화시켜 예측이 단조롭게 따라오는지 본다. 모델이 실제로 **체형에 반응**하는지,
   아니면 그냥 **인구 평균으로 회귀**하는지 분리해 낸다.
   → **실제 데이터로는 불가능한 실험.** 이 방식만의 고유 가치다.

헤드라인 벤치마크 수치는 `raw_test_data` 182명(실사진 + 실측)을 기준으로 유지한다.

## 6. 앞으로의 잠재적 문제

- **분포 편향**: 182명은 SizeKorea 스튜디오 촬영본이다. 조명·포즈·배경이 균일해
  실사용(사용자가 폰으로 찍은 사진) 성능을 과대평가할 위험이 있다.
  → "in-the-wild" 보강이 필요했던 원래 동기는 여전히 유효하다.
- **소스 선택 기준**: 보강 소스는 **레코드 1개 = 사람 1명**인 구조여야 한다.
  쇼핑몰(모델 재사용)이 아니라 학술/공개 데이터셋(1인 1레코드) 계열이어야 한다.
- **라이선스**: 쇼핑몰 이미지는 상업적 재배포·모델 학습 사용에 법적 리스크가 있다.
  벤치마크(내부 평가) 용도라도 저장소 커밋 시 주의가 필요하다.
