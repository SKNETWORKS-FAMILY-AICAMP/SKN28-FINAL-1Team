# 사진 기반 신체치수 추정 모델 평가 요약

## 1. 무엇을 평가했나

- 모델 입력: 정면 사진 1장, 측면 사진 1장, 성별, 키(cm), 몸무게(kg)
- 모델 예측: 가슴둘레, 허리둘레, 엉덩이둘레(cm)
- 정답값은 모델에 주지 않고, 호출 후에만 실제 신체치수와 비교함
- 평가 지표: 평균 절대 오차(MAE, cm) — 낮을수록 좋음 / 성공률 — 높을수록 좋음

## 2. 데이터 분할

| 구분       |  인원 | 용도                                                    |
| ---------- | ----: | ------------------------------------------------------- |
| Validation |  39명 | 모델·프롬프트 비교 및 후보 선정                        |
| Test       | 154명 | 최종 선택 모델의 한 번뿐인 최종 평가                    |
| 합계       | 193명 | SizeKorea와 기타 인물 데이터를 하나의 데이터셋으로 사용 |

- 이 실험은 별도 학습이 없는 API 기반 추론(Zero-shot)이므로, 일반적인 Train/Validation/Test 대신 `Validation → 최종 Holdout Test` 구조를 사용함
- Gemini는 Test 154명을 한 번 호출했지만 모델 선정·지표 비교에는 사용하지 않았고, 해당 예측 파일은 삭제함
- 따라서 Qwen·Kimi의 최종 Test 154명 평가는 아직 수행하지 않음

## 3. 실행 방식

- Gemini: `run_gemini.py`로 Gemini API 호출
- Qwen / Kimi / Grok: `run_openrouter.py`로 OpenRouter API 호출
- 각 호출의 예측값을 `*_predictions_*.csv`에 저장
- `evaluate_results.py`가 예측값과 정답지를 비교해 `*_evaluated_*.csv`, `*_metrics_*.json` 생성
- 모든 모델에 같은 Validation 39명, 같은 입력 정보, 같은 출력 JSON 형식을 적용

## 4. 후보 선정 기준

- 사진 2장과 키·몸무게·성별을 함께 이해하는 멀티모달 모델인지
- 가슴·허리·엉덩이 3개를 JSON으로 안정적으로 반환하는지
- 평균오차(MAE)가 낮은지
- 호출 성공률이 높은지
- 응답 시간과 이미지 포함 호출 비용이 프로젝트 범위에 맞는지

## 5-3. 데이터셋 정책 변경 — SizeKorea만 사용 (2026-08-05 결정)

기존 Test 154명은 SizeKorea 145명 + 비-SizeKorea 외부 9명으로 구성돼 있었다.
외부 데이터는 동일한 실측 기준으로 검증되지 않았기 때문에 **최종 평가 기준은
SizeKorea 실측 데이터만 사용한다.** 외부 이미지, 라벨 행, split 행, VLM 실험 CSV 행은 삭제했다.

| 집합 | 인원 | 가슴 | 허리 | 엉덩이 | 평균 MAE |
| ------------------------- | ----: | ----: | ----: | ----: | ----: |
| SizeKorea만 | 145 | 4.252 | 3.194 | 2.643 | 3.363 |
| **SizeKorea − 정답오류 2건** | **143** | **3.532** | **3.187** | **2.660** | **3.126** |

1. **최종 기준은 SizeKorea 145명이다.** 외부 프로필 기반 정답은 평가 근거에서 제외한다.
2. **정답오류 2건을 제외한 참고 수치도 유지한다.** 발표·비교 시에는 어떤 기준을
   썼는지 함께 적는다.
3. SizeKorea-only 기준 split 비율은 Test 145명(80.11%) / Validation 36명(19.89%)로 유지된다.
4. 향후 Validation·Test 재구성 시에도 SizeKorea만 후보로 사용한다.

### VLM 응답의 비결정성 (2026-08-05 관측)

`temperature=0`으로 호출하지만 **같은 사진·같은 입력에도 응답이 달라질 수 있다.**
API 종단 시연에서 8/4 배치 결과와 대조한 결과다.

| 대상 | 8/4 배치 (가슴/허리/엉덩이) | 8/5 API | 일치 |
| ------------- | ----: | ----: | ---- |
| sizkorea_f111 | 88.5 / 76.0 / 94.0 | 85.0 / 72.0 / 91.0 | 전부 다름 |

f111은 같은 입력에서 MAE 1.17cm → 3.60cm로 벌어졌다. 단건 결과를 모델 성능의
근거로 쓰면 안 되고, 평가는 항상 표본 전체 평균으로 판단해야 한다는 뜻이다.
재현이 필요한 벤치마크는 응답을 CSV로 남겨 대조한다.

## 6. 검증 결과와 해석 시 유의사항

### ⚠️ 정답 데이터 오류 2건 (Test 154명, 미수정)

최종 Test에서 **정답지 자체가 잘못된 행 2건**을 발견했다. 모델이 틀린 것이 아니다.

| subject_id | 성별 | 키 | 몸무게 | 정답지 가슴 | 모델 예측 | 판정 |
| ---------- | ---- | ----: | ----: | ----: | ----: | ---- |
| `sizkorea_m163` | M | 170.9 | 54.5 | **8.2** | 82.5 | 사람 가슴둘레 8.2cm는 불가능. 자릿수 오류로 보임(82.x → 8.2) |
| `sizkorea_m158` | M | 177.9 | 77.8 | **57.3** | 94.5 | 177.9cm/77.8kg 남성의 가슴둘레로 비정상 |

- 이 2건이 가슴 MAE를 **3.547 → 4.225로 부풀렸다** (0.678cm 왜곡)
- Validation 36명에는 동일한 오류가 **0건**이다
- 판정 기준: 가슴·엉덩이 60cm 미만 또는 허리 40cm 미만을 성인 신체치수로 비상식적인 값으로 봄
- **아직 데이터를 수정하지 않았다.** 원본 SizeKorea 값을 확인한 뒤 고쳐야 하며,
  그 전까지 Test 지표는 "전체 154명"과 "정상 152명"을 함께 표기한다
- 재확인 방법: `data/splits/vlm/test_set.csv`에서 위 두 `subject_id`의 `chest` 열

### 확인 완료

- Validation 36명과 Test 145명은 중복 인원이 0명이고, 각 split 안의 중복 ID도 0명임
- 모든 대상자에게 정면·측면 이미지가 존재하며, 키·몸무게·성별·정답 신체치수가 누락되지 않음
  (다만 값이 존재한다고 해서 타당하다는 뜻은 아니다 — 위 오류 2건 참조)
- 모델 프롬프트에는 사진·성별·키·몸무게만 렌더링되고, 실제 가슴·허리·엉덩이 수치는 모델 호출 뒤 평가 단계에서만 사용됨
- 저장된 모든 모델 지표는 예측 CSV에서 다시 계산해 일치함
- 성별 분포: Validation F 19명 / M 20명, Test F 74명 / M 80명으로 균형이 유지됨

### 분할의 타당성

- 학습을 하지 않는 실험이므로 Validation 20%(39명)로 후보를 고르고 Test 80%(154명)로 최종 성능을 확인하는 구조는 타당함
- 다만 일반적인 학습 실험의 70/15/15 분할과는 목적이 다르므로, 문서에서는 `학습 없는 Zero-shot 모델 비교`라고 명시해야 함
- 엄격하게 모든 모델을 동일한 test로 비교해야 한다면 새로운 holdout set을 별도로 만들어야 함. 현재 Test 154명은 Qwen·Kimi에는 아직 사용되지 않았음

### 해석 한계와 보완할 점

- Kimi가 Qwen보다 평균 MAE가 0.841cm 낮았고, 같은 39명을 이용한 95% 부트스트랩 구간은 -1.418~-0.293cm로 Kimi 우세 방향이 유지됨
- Qwen과 Grok의 차이는 0.156cm이고 95% 구간이 -0.378~0.691cm라, 39명만으로 둘의 우열을 단정하기 어려움
- SizeKorea 외 데이터는 Validation 3명뿐이라 출처별 성능을 일반화할 수 없음
- API 모델은 제공자·시점에 따라 응답이 달라질 수 있으므로, 최종 후보는 10명 내외를 3회 반복 호출해 결과 흔들림도 확인하는 것이 좋음
- 전체 평균만으로는 부족하므로, 최종 Test에서는 성별·출처별 MAE와 큰 오차 사례도 함께 보고해야 함

## 6-1. ⚠️ 아직 없는 숫자 — 무사진 기준선 (2026-08-05 확인)

**이 문서에는 "사진을 써서 3.15cm"라는 결과만 있고, 같은 사람들을 사진 없이
성별·키·몸무게만으로 예측했을 때의 오차가 없다.** 그 숫자가 없으면 사진이 실제로
도움이 됐는지 판단할 근거가 없다.

- 1단계 tabular 보고서의 **1.915cm를 여기에 갖다 대면 안 된다.** 그건 SizeKorea 5,092명
  모집단에서 나온 값이고, 여기 평가셋은 별도 촬영 데이터셋이다. 모집단·측정 프로토콜이
  달라 차이가 사진 덕분인지 데이터가 쉬워서인지 구분되지 않는다
  (근거: `docs/multimodal-model-selection.md` §0).
- 판정식: **같은 split 행에서** `MAE(VLM, 사진 사용)` < `MAE(tabular, 사진 없음)`.
- 산출 스크립트를 만들어 뒀다 — `src/no_photo_baseline.py`.

```powershell
cd ml\body_measurement

# ① 컬럼 정의 확정 — split의 chest가 SizeKorea의 `가슴둘레`인지 `젖가슴둘레`인지 판정
#    (두 항목은 평균 2.47cm 차이라 잘못 잡으면 모델 오차보다 큰 편향이 생긴다)
python src\no_photo_baseline.py --drop-impossible match

# ② 무사진 기준선 + 사진 有/無 비교
#    ①에서 확정한 매핑을 no_photo_baseline.py의 CONFIRMED_MAPPING에 반영한 뒤 실행
python src\no_photo_baseline.py --drop-impossible baseline
```

⚠️ **스크립트는 아직 한 번도 실행되지 않았다** (작성 세션에서 Python 실행이 권한으로
차단됨). 문법·동작 검증 전이므로 첫 실행 시 오류가 날 수 있다.
